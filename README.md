# ЛР 4. Алгоритмический мини-пакет

`algolab` вычисляет целые степени, сортирует списки, демонстрирует работу стека и сравнивает две сортировки на воспроизводимых наборах. Требуется Python 3.12+.

## Установка и запуск

В PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m algolab --help
```

## Реализованный функционал

### Быстрая степень

```powershell
python -m algolab recurrent --iter 2 10
# 1024
python -m algolab recurrent --recur -3 3
# -27
```

Функции `iter()` и `recur()` принимают целые основание и показатель. При нулевом показателе результат равен 1, в том числе для `0 ** 0`. Отрицательная степень вызывает `ValueError`, а при прямом вызове из Python аргумент неверного типа, включая `bool`, вызывает `TypeError`.

Цикл возводит основание в квадрат и делит показатель нацело на два. Перед делением при нечётном показателе основание домножается в результат. Рекурсия использует равенства `a^(2m) = (a²)^m` и `a^(2m+1) = a · a^(2m)`.

Текущую глубину рекурсии, которую допускает Python, показывает `python -c "import sys; print(sys.getrecursionlimit())"`. В окружении контрольного запуска лимит равен 1000. Показатель степени может быть больше, так как он уменьшается примерно вдвое за один-два вызова. При исчерпании стека Python поднимает `RecursionError`. Вариант `--iter` работает без рекурсии.

### Сортировки

```powershell
python -m algolab sorting --effective 5 -2 5 1
# [-2, 1, 5, 5]
python -m algolab sorting --quadratic --reverse 3 -1 3 2
# [3, 3, 2, -1]
```

- **Пузырьковая (`--quadratic`).** Сравнивает соседей и меняет их местами при нарушении порядка. После каждого прохода один крайний элемент встаёт на своё место.
- **Слиянием (`--effective`).** Делит список пополам, рекурсивно сортирует половины и сливает их в один список.
- **Вход и результат.** Обе функции возвращают новый список, включая входы из нуля или одного элемента. Поддерживаются повторы и отрицательные числа. По умолчанию порядок возрастающий, для убывания есть `--reverse`. При прямом вызове кортеж вместо списка или сравнение несовместимых элементов, например `[1, "2"]`, дают `TypeError`. `sorted()` используется как эталон в тестах. Обе реализации сравнивают элементы через `<` и обходятся без `sorted()` и `list.sort()`.

### Стек

```powershell
python -m algolab struct
```

`push(x)` кладёт элемент на вершину, `peek()` возвращает вершину без удаления, `pop()` снимает её. `len(s)` даёт размер, `bool(s)` показывает, есть ли элементы. Для пустого стека `peek()` и `pop()` поднимают `IndexError`.

Стек работает по принципу LIFO. После `push(x)` очередной `pop()` вернёт именно `x`, а прежние размер и вершина восстановятся. На этом свойстве основан отдельный [тест инварианта](tests/test_power_stack_generators.py).

### Генераторы списков

```powershell
python -m algolab generate --kind almost-sorted --size 10 --seed 42
```

| Имя | Как строится список из `size` элементов |
|---|---|
| `random` | Независимые псевдослучайные целые от −1000 до 1000 включительно |
| `sorted` | Числа от 0 до `size - 1` по возрастанию |
| `reverse` | Те же числа в обратном порядке |
| `almost-sorted` | При длине от 2 меняются местами `max(1, size // 20)` непересекающихся соседних пар |
| `duplicates` | Каждое значение выбирается из чисел 0–4. Например, при длине 1000 различных чисел будет не более пяти |

Размер 0 даёт пустой список, отрицательный размер вызывает `ValueError`. Для случайных наборов используется отдельный `random.Random(seed)`. Одинаковые тип, размер и `seed` воспроизводят один список. Разные значения `seed` обычно дают разные случайные наборы. Для `sorted` и `reverse` данные определяются размером.

## Benchmark и результаты

Команда `python -m algolab benchmark sorting` сравнивает два алгоритма на пяти типах входа и размерах 100, 1000 и 10000. Для быстрой проверки можно задать `--sizes 10 100 --seed 42`. Сохранить полный отчёт в PowerShell можно командой:

```powershell
python -m algolab benchmark sorting | Out-File results.md -Encoding utf8
```

Для каждой пары размера и типа генератор один раз строит исходный список. Перед каждым запуском сортировки берётся его независимая копия. Таймер `perf_counter()` включается после подготовки и останавливается сразу после вызова. Для каждой ячейки взята медиана пяти измерений, а всего выполнено 150 измерений. Если передавать один изменяемый список, сортировка на месте может оставить его отсортированным для последующих повторов и исказить сравнение. Обеим реализациям предоставляются одинаковые начальные условия.

Результат контрольного запуска на Windows x64, CPython 3.14.7, `seed=42`. Время указано в миллисекундах.

| Тип входа | Размер | Пузырьковая, мс | Слиянием, мс |
|---|---:|---:|---:|
| random | 100 | 0.259 | 0.108 |
| sorted | 100 | 0.181 | 0.074 |
| reverse | 100 | 0.275 | 0.080 |
| almost-sorted | 100 | 0.183 | 0.073 |
| duplicates | 100 | 0.231 | 0.100 |
| random | 1000 | 29.838 | 1.317 |
| sorted | 1000 | 20.812 | 0.863 |
| reverse | 1000 | 31.518 | 1.032 |
| almost-sorted | 1000 | 20.903 | 0.933 |
| duplicates | 1000 | 27.171 | 1.268 |
| random | 10000 | 3207.639 | 15.916 |
| sorted | 10000 | 2339.926 | 16.462 |
| reverse | 10000 | 3465.771 | 11.113 |
| almost-sorted | 10000 | 2322.330 | 11.151 |
| duplicates | 10000 | 2767.078 | 14.897 |

При десятикратном увеличении случайного списка с 1000 до 10000 элементов время пузырьковой выросло примерно в **108 раз**, а сортировки слиянием — примерно в **12 раз**. Для пузырьковой число сравнений равно `n(n−1)/2`, даже на отсортированном входе. Для слияния число уровней растёт логарифмически, а работа по объединению всех серий на одном уровне пропорциональна `n`. Измеренный рост согласуется с этими оценками. Конкретное время зависит от машины и нагрузки.

## Время и память

| Алгоритм | Время | Память |
|---|---|---|
| Быстрая степень, цикл | O(log(d + 1)) шагов при показателе d > 0, O(1) при d = 0 | O(1) целочисленных переменных |
| Быстрая степень, рекурсия | O(log(d + 1)) шагов при d > 0, O(1) при d = 0 | O(log(d + 1)) кадров при d > 0 |
| Пузырьковая сортировка | Θ(n²) сравнений в этой реализации | O(n) для возвращаемой копии, O(1) сверх неё |
| Сортировка слиянием | O(n log n) в худшем случае | O(n) пиковая память для списков и O(log n) вложенных вызовов |
| Стек | `push` и `pop` с конца — амортизированно O(1), `peek`, `len`, `bool` — O(1) | O(n) для хранения n элементов |
| Генераторы | O(n) | O(n) с учётом результата |

Для степени подсчитаны арифметические операции. У целых чисел Python произвольная точность, поэтому время умножения и размер чисел в байтах растут вместе с их разрядностью.

## Тесты и критерии сдачи

После установки запустите `python -m pytest -q` или `python -m unittest discover -s tests -v` из корня проекта. Для запуска стандартной библиотекой непосредственно из каталога `src` используйте `python -m unittest discover -s ../tests -v`.

| Критерий из grading | Максимум | Что проверяется |
|---|---:|---|
| Два варианта рекуррентной задачи | 12 | Сравнение с целочисленной степенью, большие целые, показатель 0, неверный ввод |
| Квадратичная сортировка | 10 | Результат, сохранение входа, границы и сравнение с эталоном |
| Эффективная сортировка | 15 | Те же проверки, слияние равных и ограничение числа сравнений |
| Структура данных | 13 | Операции стека, LIFO, логическое значение и исключения |
| Генераторы | 10 | Размер, порядок, частые повторы, воспроизводимость и разные seed |
| Benchmark | 12 | Повторы (3), размеры и типы (3), независимые входы (2), таблица (2), интерпретация (2) |
| Анализ сложности | 8 | Время и дополнительная память для реализованных алгоритмов |
| Автоматические тесты | 15 | Сортировки (5), стек (3), степень (2), генераторы (3), независимость от времени и глобальной случайности (2) |
| Структура проекта и защита | 5 | Запуск пакета, объяснение сложности слияния, тест инварианта стека и обоснование копий |
| **Всего за обязательную часть** | **100** | Баллы выставляются на защите |

Тесты включают пустой список, один элемент, отсортированный и обратный вход, отрицательные числа и дубликаты. Результаты обеих сортировок проверяются на случайных списках с фиксированным локальным seed. Для слияния тест считает сравнения на четырёх типах входа. В проверках benchmark часы подменяются заданной последовательностью показаний, поэтому результат тестов не зависит от скорости компьютера. [Проверки методики benchmark и CLI](tests/test_benchmark_cli.py)

Из дополнительных заданий в проекте показаны стабильность с тестовым подтверждением и автоматический Markdown-отчёт. По grading встроенная сортировка внутри алгоритма обнуляет соответствующий критерий, методологически неверный benchmark ограничен 4 из 12, а отсутствие анализа сложности обнуляет его 8 баллов. При отсутствии обязательных тестов итог ограничен 59 баллами.
